# 1. 目的

AWS上のWordPress共通環境に合わせて、ECサイト独自のログイン・ユーザー登録・認証処理を安全に設計する。

本設計では、データベースはプロジェクト方針に合わせて **SQLiteを継続使用** する。

---

# 2. 前提

本プロジェクトでは、WordPress上に共通環境を構築するが、ログイン画面や認証処理はECサイト側で独自に用意する。

```text
ログイン画面
↓
PHPバックエンド
↓
入力値チェック
↓
パスワード検証
↓
SQLite usersテーブル
↓
ログイン成功 / 失敗
```

# 5. ユーザー登録処理

対象ファイル：

```text
src/auth/register_process.php
```

## 処理フロー

```text
register.php
↓
ユーザー名・メールアドレス・パスワード入力
↓
register_process.php
↓
入力値チェック
↓
メールアドレス重複チェック
↓
password_hash() でパスワードをハッシュ化
↓
usersテーブルへ保存
↓
登録完了
```

## register_process.php の役割

* POSTされた入力値を受け取る
* 未入力チェックを行う
* メールアドレス形式を確認する
* 同じメールアドレスが登録済みでないか確認する
* パスワードを平文保存せず、ハッシュ化して保存する
* 登録結果を画面へ返す

# 6. ログイン認証処理

対象ファイル：

```text
src/auth/login_process.php
```

## 処理フロー

```text
login.php
↓
メールアドレスまたはユーザー名・パスワード入力
↓
login_process.php
↓
入力値チェック
↓
usersテーブルから対象ユーザーを取得
↓
password_verify() でパスワードを検証
↓
認証成功
↓
ログイン状態を保存
↓
マイページへ遷移
```

## login_process.php の役割

* POSTされたログイン情報を受け取る
* 未入力チェックを行う
* `users` テーブルからユーザー情報を取得する
* 入力されたパスワードとDB上のハッシュ化済みパスワードを照合する
* 成功時はログイン状態を保持する
* 失敗時はエラーメッセージを返す

# 8. パスワード管理ルール

## 禁止事項

```text
パスワードを平文でDB保存することは禁止
```

## 登録時

```text
入力パスワード
↓
password_hash()
↓
ハッシュ化済みパスワード
↓
users.password に保存
```

## ログイン時

```text
入力パスワード
↓
password_verify()
↓
users.password と照合
↓
成功 / 失敗
```

## 変更コメント

* 独自暗号化ではなく、PHP標準の `password_hash()` / `password_verify()` を使用する
* DBには元のパスワードを保存しない

# 10. SQLiteファイルの隠蔽

## 禁止配置

```text
public/app.sqlite
```

理由：

ブラウザから直接ダウンロードされる危険があるため。

## 推奨配置

```text
database/app.sqlite
```

理由：

`public/` の外に配置することで、外部から直接アクセスされにくくする。

---

# 11. .htaccess 設定

対象ファイル：

```text
public/.htaccess
```

## 目的

万が一SQLiteファイルが公開ディレクトリ内に置かれた場合でも、直接アクセスを防ぐ。

```apache
<Files "*.sqlite">
    Require all denied
</Files>
```

# 12. エラー表示ルール

ログイン失敗時に、詳細すぎる情報を表示しない。

## NG例

```text
このメールアドレスは存在しません
```

```text
パスワードが間違っています
```

## OK例

```text
メールアドレスまたはパスワードが正しくありません
```

理由：

攻撃者に、登録済みメールアドレスや正しい情報を推測されにくくするため。

# 16. 共有メモ

今回の主対象は #37〜#39 のログイン認証機能。

ただし、ログイン状態を終了する処理も認証機能と関係が深いため、#40〜#41 のログアウトも関連機能として設計に含める。

そのため、WordPress環境に移行しても、認証用DBとして `database/app.sqlite` を安全な場所に配置し、PHPからPDOで接続する方針とする。
